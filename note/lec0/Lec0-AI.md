### 🗺️ 第一阶：结构大纲（提问式骨架）

*（把作者思路还原为几个核心拷问，理清逻辑线）*

1. **操作系统（OS）到底是干嘛的？（核心四职责）**
   - 共享资源、抽象硬件、多路复用（假装同时跑）、提供受控交互。
2. **OS怎么和你沟通？（接口与机制）**
   - 通过**系统调用**（System Call）。设计哲学：机制少而精，组合起来功能强大。
3. **进程是啥？怎么造出来？（进程 + fork/exec）**
   - 进程=运行中的程序（指令+数据+栈）。
   - 造人术：`fork()` 复制（分身），`exec()` 变身（换脑）。**记住：先复制再变身，中间可以偷偷改环境（这是重定向的关键）。**
4. **怎么操作文件和外设？（文件描述符 fd）**
   - fd 就是个**整数代号**（0输入，1输出，2错误）。统一万物为“字节流”。
5. **进程间怎么传话？（管道 pipe）**
   - 内存里的临时缓冲区，自带**同步阻塞**和**自清洁**功能，比临时文件高级。
6. **文件系统长啥样？（目录树 + inode）**
   - 树形结构。`inode` 是本体，`文件名` 是标签（链接）。`unlink` 删标签，标签数为0才真删除。

### 🧠 第二阶：核心降维（用大白话“翻译”抽象概念）
*（这是考试面试最爱考的地方，必须秒懂）*

- **关于 `fork()` 和 `exec()` 为什么不合并？** 
  - **神比喻**：`fork()` 是 **“克隆自己”**（连衣服都复制），`exec()` 是 **“灵魂附体/换皮肤”**（身体还是那个进程，但灵魂换成了新程序）。
  - **为啥分开**：因为 shell 要在“克隆体”执行新程序**之前**，偷偷把它的 `标准输入(0)` 换成文件（重定向）。如果合在一起，你就没机会做手脚了。

- **关于“文件描述符”的抽象威力：**
  - **神比喻**：fd 就像**“插座接口”**。无论是插在硬盘（文件）、键盘（控制台）还是管道（内存缓冲区）上，程序（比如 `cat`）只管对着这个“插座”读/写 `read/write`，它根本不用管背后插的是什么电器。这就是“一切皆文件”的雏形。

- **关于“管道 vs 临时文件”：**
  - 管道是**“实时聊天”**（一边写一边读，写不完读端就等着，自动同步）；临时文件是**“写信寄信”**（写完了存成文件，再去读，还得自己打扫卫生删文件）。

### 🎯 终极拷问（如果只考一道论述题，必考这道）
**题目**：请结合 `fork`、`exec`、`文件描述符` 和 `管道`，详细阐述 Shell 执行命令 `ls | grep "txt" > output.txt` 的底层原理。

**（附赠标准答题框架供你参考）**
1. Shell 父进程调用 `fork()` 创建子进程。
2. 子进程内部先调用 `pipe()` 创建管道，得到读端(p[0])和写端(p[1])。
3. 子进程再次 `fork()` 出左右两个子进程（或者通过重定向标准输出到写端，标准输入到读端）。
4. 执行 `ls` 的子进程：`close(1)`，`dup(p[1])` 让 1 指向管道写端，然后 `exec("ls")`。
5. 执行 `grep` 的子进程：`close(0)`，`dup(p[0])` 让 0 指向管道读端，然后 `exec("grep")`。
6. 最外层子进程：`close(1)`，`open("output.txt")`（此时最小未用fd=1），然后 `exec("grep")` 把结果写进去（但实际上重定向应该在grep端做完，精讲略，意会流程）。
*(核心得分点：文件描述符的复制和重定向发生在 `fork` 之后，`exec` 之前)*
