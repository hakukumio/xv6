# xv6-makefile导读

欢迎来到操作系统的“建筑工地”。这份 Makefile 不是普通的软件构建脚本，它是 **MIT 6.1810（原 6.828）xv6 操作系统实验室**的“总施工图纸”。

作为老师傅带你看，我不会教你背诵语法，而是带你**沿着 `make qemu` 这条命令的执行路径，进行一次“源码级”的探险**。我们会像剥洋葱一样，一层层看这个系统是如何从零构建出来的。

---

### 第一站：入场准备（顶部的“魔法配置”）

```makefile
-include conf/lab.mk
K=kernel
U=user
```
- **`-include`**：前面的减号 `-` 意味着“即使这个文件不存在，也别报错，继续往下走”。这是高手的容错写法。
- **`K` 和 `U`**：这是给目录起外号。以后看到 `$K` 就是 `kernel/` 目录，`$U` 就是 `user/` 目录。这样做是为了**避免硬编码**，万一以后目录改名，只改这一处就行。

---

### 第二站：探测“异星环境”（工具链自动检测）

```makefile
ifndef TOOLPREFIX
TOOLPREFIX := $(shell if riscv64-unknown-elf-objdump -i ...; then ...)
endif
CC = $(TOOLPREFIX)gcc
```
这是老师傅的**防御性编程**精髓。xv6 跑在 RISC-V（一种CPU架构）上，你的电脑（x86）无法直接编译它，需要专门的“交叉编译器”。

- 这段代码不是在编译，而是在**“问路”**。它依次尝试三个常见的 RISC-V 编译器前缀（`unknown-elf`、`linux-gnu` 等）。
- 哪个能运行，就用哪个。如果都找不到，直接打印三个星号报错并退出。**这避免了新手因为环境变量没配好而编译出一堆天书报错。**

---

### 第三站：内核的“钢铁骨架”（OBJS 变量）

```makefile
OBJS = \
  $K/entry.o \
  $K/start.o \
  ...
  $K/virtio_disk.o \
```
这里定义了 **30 多个 `.o` 文件**。请把它们想象成**拼图碎片**：

- `entry.o` 是开机启动的第一行汇编（入口）。
- `main.o` 是 C 语言世界的入口。
- `virtio_disk.o` 是硬盘驱动。

**注意看条件编译**：
```makefile
ifeq ($(LAB),pgtbl)
OBJS += $K/vmcopyin.o
endif
```
如果你正在做“页表（pgtbl）”这个实验，系统会多拼一块 `vmcopyin.o` 进去。这说明同一份 Makefile 支撑了 6 个不同的实验，**通过 `LAB` 变量动态调整内核大小**。

---

### 第四站：编译内核（心脏搭桥手术）

```makefile
$K/kernel: $(OBJS) $K/kernel.ld $U/initcode
	$(LD) $(LDFLAGS) -T $K/kernel.ld -o $K/kernel $(OBJS) 
	$(OBJDUMP) -S $K/kernel > $K/kernel.asm
	$(OBJDUMP) -t $K/kernel | ... > $K/kernel.sym
```
这是**整个 Makefile 最重要的手术台**：

1. **依赖关系**：要生成 `kernel`（最终内核文件），必须先把那 30 多个 `.o` 拼图、链接脚本（`kernel.ld`）和用户态的第一个程序（`initcode`）准备好。
2. **链接（LD）**：`-T $K/kernel.ld` 意味着“按照这张内存地图（链接脚本）把碎片拼接到指定的内存地址上”。操作系统内核不能乱放，必须放在物理内存的特定位置（通常是 0x80000000）。
3. **副产品**：链接完成后，顺手生成 `kernel.asm`（汇编代码，供调试）和 `kernel.sym`（符号表，供调试器看函数地址）。

### 第五站：用户态程序（一堆“小工具”）

```makefile
UPROGS=\
	$U/_cat\
	$U/_echo\
	...
	$U/_sh\
```
Linux 下有 `ls`、`cat`，xv6 里也有。这里的 `_cat`、`_sh` 就是**操作系统里的应用程序**。

**重点看这条通用规则**：
```makefile
_%: %.o $(ULIB)
	$(LD) $(LDFLAGS) -N -e main -Ttext 0 -o $@ $^
```
- `_%` 是个通配符。当你编译 `make _cat` 时，它会自动去找 `cat.o`。
- **`-Ttext 0`** 极其关键：**用户程序的起始虚拟地址从 0 开始**。这是操作系统内存隔离的精髓——内核在高地址（2GB以上），用户程序在低地址（0）。老师傅写这条规则，就是为了让每个用户程序都统一从 0 地址启动。

---

### 第六站：打包硬盘镜像（最关键的一步）

```makefile
fs.img: mkfs/mkfs README $(UEXTRA) $(UPROGS)
	mkfs/mkfs fs.img README $(UEXTRA) $(UPROGS)
```
内核编译好了，用户程序也编译好了，但它们分散在硬盘上。**`fs.img` 就是一个虚拟硬盘的镜像文件**。

- 这里调用了一个自己写的小工具 `mkfs/mkfs.c`（用你本机的 `gcc` 编译的）。
- 它把这些程序（`_cat`、`_sh`）和文件（`README`）**按固定的文件系统格式**，全部打包进一个叫 `fs.img` 的大文件里。

**当 QEMU 模拟器启动时，它加载的就是这个 `fs.img` 作为它的“C盘”。**

---

### 第七站：启动 QEMU（上战场）

```makefile
QEMUOPTS = -machine virt -kernel $K/kernel -m 128M -drive file=fs.img,...
qemu: $K/kernel fs.img
	$(QEMU) $(QEMUOPTS)
```
终于到了最后！当你输入 `make qemu`：

1. Make 检查 `kernel` 和 `fs.img` 是否最新，不是则重新编译。
2. 执行 `qemu-system-riscv64`，将内核加载到模拟内存，将 `fs.img` 挂载为硬盘。
3. 屏幕弹出一个黑框，里面就是 xv6 操作系统在运行。

---

### 第八站：隐藏的“大师细节”（必须提的三处）

作为一个带新手的老师傅，我必须指着这三处告诉你什么叫“工程洁癖”：

**1. 依赖文件包含（`-include kernel/*.d user/*.d`）**
你注意到编译时每个 `.c` 文件旁边会生成一个 `.d` 文件吗？那是自动生成的**头文件依赖**。如果不包含它们，你修改了 `param.h`，但 `proc.c` 不会重新编译。**有了这行，改一个头文件，所有相关源文件自动重编，无需手动 `make clean`。**

**2. `.PRECIOUS: %.o`（结合你上一个问题）**
这行代码保护了所有 `.o` 文件。如果不加，Make 会认为 `.o` 是临时工，编译完内核就把它删了。加上后，`.o` 变成正式工，**这保证了你第二次编译时不需要从头开始，增量编译秒级完成。**

**3. GDB 调试端口自动分配**
```makefile
GDBPORT = $(shell expr `id -u` % 5000 + 25000)
```
如果你和同学共用一台服务器，两个人同时 `make qemu-gdb` 调试，端口会冲突。这里用你的 Linux 用户 ID（`id -u`）算出一个唯一端口（25000~30000之间），**保证多人同时调试互不干扰**——这是高校实验服务器的标配骚操作。

### 师傅给你的“心法口诀”

读这种级别的 Makefile，千万不要试图背每一行。你只需要记住这张 **“构建流水线”** 图：

> **C源码 (.c/.S)** 
> → 编译（gcc）→ **目标文件 (.o)** 
> → 链接（ld）→ **内核/用户程序** 
> → 打包（mkfs）→ **硬盘镜像 (fs.img)** 
> → 加载（QEMU）→ **运行的操作系统**

这份 Makefile 中的所有代码，**都是在为这条流水线上的每一道工序指定“工人（编译器）”、“工具（ld/objcopy）”和“工艺参数（-Ttext、-mcmodel）”**。

你现在看不懂那些复杂选项（如 `-mcmodel=medany`）很正常，那是 RISC-V 底层寻址的特殊要求。作为新手，你只需要知道：**老师傅已经把最难的坑（环境检测、增量编译、调试端口）都替你填平了，你只需要在 `$K/` 和 `$U/` 目录下改你的 `.c` 代码，然后敲一个 `make qemu`，世界就运转起来了。**

如果把它比作开车，这份 Makefile 就是这辆车的**全自动启动电门和变速箱**。你不需要知道齿轮怎么啮合，但看完师傅的讲解，你至少知道油门（`make`）在哪，档位（变量）在哪，以及为什么这车永远不会在红灯时熄火（`.PRECIOUS` 保护）。带着这种视角去读，它就不再是天书了。还有什么具体模块觉得卡壳，随时截出来问师傅。
