# 06 — 会话协议

## 状态版本机制

- `04-progress.md` 与 `07-pitfalls.md` 头部有版本日期。
- 新模型启动时：先看版本日期，再决定信任 `01-handoff.md` 快照还是 `04/07`。
- **约定：`04/07` 永远比 `01` 快照新。**

## 会话开始

- 换新模型：学生贴 `01-handoff.md` 全文。
- 旧模型续聊：学生说「请先读 prompt/ 全套，以 TA 身份继续」。
- 模型必须先复述「进度 + 下一步 + 薄弱点」，确认读对后再开讲。

## 会话结束（TA 负责或提醒学生）

1. 更新 `04-progress.md`：
   - 进度总表（新完成的题）
   - 「下一步」清单勾选 / 追加
   - 「最近会话记录」追加一行（日期 + 干了什么 + 遗留什么）
2. 更新 `07-pitfalls.md`：新增坑、复发计数。
3. 刷新 `01-handoff.md` 状态快照（版本日期 + 关键点）。
4. 所有文件的头部版本日期改为当天。

## 教学节奏

- 大方向遵循 `04-progress.md` 的「下一步」；学生跑偏时拉回。
- 讲题按 `02-ta.md` 原则；每完成一个 lab 做阶段小结。
- 涉及新主题时按 `05-resources.md` 指路（book 章节 / lecture / 源码）。

## 换模型检查清单（学生用）

- [ ] `01-handoff.md` 快照日期 = 最近一次会话
- [ ] `04/07` 版本日期最新
- [ ] 新模型能正确复述进度与下一步
